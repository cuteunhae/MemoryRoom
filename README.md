# 도시 속 빛나는 존재

현재 구현 범위는 도시 탐색, 사진관·학교·집의 임시 실내 출입, 사진첩 클릭 조사와 인벤토리입니다. 도시와 실내 물체는 임시 도형으로 표시합니다.

## 실행 방법

1. VS Code에서 **터미널 → 새 터미널**을 엽니다. 프로젝트 폴더에서 `node server.cjs`를 실행합니다.
2. Edge 또는 Chrome에서 **http://127.0.0.1:8000**을 엽니다.
3. 방향키 `↑` `↓` `←` `→`로 이동합니다. 두 방향키를 함께 누르면 대각선으로 이동합니다. 시작 위치는 가운데 별 모양 원형 광장(논리 좌표 `(748, 640)`)입니다.
4. 사진관·학교의 입구 또는 집 뒤편 쪽문 가까이에서 **E 키를 누르거나 문을 왼쪽 클릭**하면 실내로 들어갑니다. 문 앞에서는 문 한가운데에 안내가 나타납니다.
5. 실내의 **나가기** 문 가까이에서 **E 키를 누르거나 문을 클릭**하면 들어왔던 입구 앞의 안전한 위치로 돌아옵니다.

게임 화면은 여백 없이 브라우저 창을 채우며, 창 크기를 바꾸면 자동으로 맞춰집니다.

지도 데이터를 별도 파일로 분리하여 프로젝트 규칙에 따라 로컬 서버 방식으로 실행합니다. Node.js가 필요하며, 추가 패키지 설치나 인터넷 연결은 필요하지 않습니다. 서버를 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

코드를 수정한 뒤 파일을 저장하고 브라우저를 새로고침하면 변경 사항이 반영됩니다.

이번 변경은 서버 파일 목록도 추가합니다. 기존 서버가 실행 중이면 `Ctrl+C`로 종료한 뒤 `node server.cjs`로 다시 실행하세요.

## 자동 저장과 새 게임

아이템 획득, 퍼즐 완료, 업적 달성, 장소·층 이동, 개별 놀이시설 이용, 아이 방 잠금 해제와 일기장 완료를 자동 저장합니다. 이동 위치는 1초 간격으로 저장하고, 탭을 떠나거나 페이지를 닫을 때도 저장합니다. 같은 브라우저의 **같은 주소(http://127.0.0.1:8000)**로 다시 열면 이어서 시작합니다. `localhost`나 다른 포트는 별도 저장 공간입니다.

진행 데이터의 localStorage 키는 `memoryRoom.progress`입니다. 기획서 6.5에는 구체적인 구조가 없어 사용자 확인을 거쳐 아래 구조를 사용합니다.

| 필드 | 내용 |
| --- | --- |
| `saveVersion` | 현재 3. 기존 1·2버전의 진행을 유지하고 힌트·엔딩 완료 상태를 보완하여 변환 |
| `inventory`, `acquiredItems` | 보유 아이템·선택 항목·중복 획득 방지 기록 |
| `puzzles` | 사진·명부·회전목마·개별 놀이시설·장식장·아이 방·일기장·메모 지급 대기 등의 상태 |
| `cabinet` | 완료한 장식장 배치만 유지. 미완료 배치는 빈칸 |
| `achievements`, `achievementConditions` | 업적 상태와 달성 조건 기록 |
| `position` | 장소 ID·학교 층·좌표·바라보는 방향·실내에서 나올 위치 |
| `hints` | 본 힌트 ID 목록·최초 확인 단서·마지막 진전 시각·진전 없는 실제 표시 시간 |

명부 문지르기, 회전목마 오답 입력, 읽던 일기장 페이지, 미완료 장식장 배치는 저장하지 않습니다. 미완료 장식장은 **저장 사본에서 아이템을 전부 반환하고 칸을 비운 뒤 한 번의 setItem으로 기록**합니다. 실행 중 배치는 그대로이며, 새로고침 후에는 인벤토리로 복원됩니다. 완료한 배치와 열쇠 지급은 유지되어 중복 지급되지 않습니다.

화면 왼쪽 위 **처음부터** 버튼을 누르면 확인창이 뜹니다. 취소하면 그대로 유지하고, 확인하면 진행만 초기화합니다. 개발 중에는 `city-data.js`의 `debug: true` 상태에서 **Ctrl+Shift+Delete**로 같은 확인창을 열 수 있습니다. 일반 모드에서는 이 단축키로 게임 저장을 지우지 않습니다.

키·소리 설정은 `memoryRoom.preferences`에 별도로 저장하며 새 게임에서도 유지합니다. 설정 화면에서 키를 변경하면 실제 조작에 바로 반영됩니다. 소리 파일은 아직 없어 배경음악·효과음 볼륨 값만 각각 저장합니다.

깨진 JSON, 잘못된 형식·지원하지 않는 버전·위치는 안내 후 새 게임으로 복구합니다. 1·2버전 저장은 3버전으로 자동 변환하여 기존 진행을 유지합니다. 저장 공간 접근이 차단되거나 용량이 부족하면 안내를 표시하고 현재 세션은 계속 진행합니다. 저장 실패 시 기존 기록을 먼저 지우지 않습니다.

- `data/save.js`: 저장 키, 버전, 위치 저장 간격, 초기화 단축키, 기본 설정과 안내 문구.
- `save.js`: 저장·검증·복원, 미완료 장식장 반환, 설정 분리, 새 게임 확인.
- `node verify-save.cjs`: 새 세션 복원, 실내·층·퇴장 위치, 아이템 유실·중복 방지, 완료 상태, 메모 지급 대기, 설정 유지, 손상·버전·저장 실패 검증.

서버를 재시작한 뒤 **아이템 획득 → 이동 → 새로고침 → 위치·인벤토리 확인**으로 확인하세요. 장식장에 일부 아이템을 놓고 새로고침하면 빈 장식장과 반환된 아이템을 확인할 수 있습니다.

## 설정과 지도

기본 **Esc** 또는 화면 오른쪽 아래 **설정** 버튼으로 설정을 엽니다. 상세창(인벤토리·대화·입력·일기장·업적·힌트·지도) 안에는 설정 버튼이 없습니다. 설정 키가 할당 없음이면 창을 닫은 뒤 오른쪽 아래 버튼으로 엽니다. 다른 창 위에서 설정을 닫으면 원래 창과 읽던 페이지가 유지됩니다. 설정이 열린 동안 이동과 아래 화면 조작은 막힙니다.

이동 네 방향·지도·인벤토리·업적·설정 중 항목을 클릭한 뒤 새 단일 키를 누릅니다. 이미 쓰던 키라면 기존 기능은 **할당 없음**으로 바뀝니다. 키 지정 중에는 Esc도 새 키로 지정할 수 있으므로 취소하려면 **키 지정 취소** 버튼을 누르세요. 설정 키를 다른 기능에 넘겼다면 마우스 설정 버튼으로 열고 **키 기본값 복원**을 누르면 됩니다. 복원은 키만 바꾸며 소리 값은 유지합니다.

배경음악과 효과음은 각각 0~100%로 저장합니다. 나중에 소리를 붙일 때 `getSoundVolume("bgm")`, `getSoundVolume("sfx")`의 0~1 값을 사용하면 됩니다. 이전 단일 볼륨 저장도 두 채널로 변환해 읽습니다. 설정 화면의 **처음부터**는 기존과 같은 확인창을 사용하고 키·소리는 유지합니다.

기본 **M**으로 전체 도시 지도를 열고 닫습니다. 도시 그림(`assets/city-map.png`)을 그대로 보여주며, 장소명·현재 위치·디버그 정보는 표시하지 않습니다. 북쪽은 위쪽이며 회전·줌 조작은 없습니다. 지도 키를 바꾸면 새 키로 열고 닫습니다.

- `data/settings.js`: 기본 키, 설정 항목·화면 문구.
- `input.js`: 변경 가능한 키 입력과 중복 없는 동작 연결.
- `settings-ui.js`: 설정·키 지정·볼륨·기본값 복원.
- `map-ui.js`: 고정 방향 플레이어 지도.
- `node verify-settings.cjs`: 실제 키 이동, 키 중복 해제, 마우스 복구, 다른 창으로 복귀, 지도, 볼륨·설정 저장과 새 게임 유지 검사.

서버를 재시작하고 새로고침한 뒤 **Esc → 항목 클릭 → 새 키 입력 → 닫기 → 변경한 키 사용**으로 확인하세요. 지도는 기본 M으로 확인합니다.

## 힌트

새 아이템 획득, 퍼즐 완료, 시설 최초 이용, 단서 최초 확인 없이 **게임을 보고 있는 시간이 3분** 쌓이면 왼쪽에 🎁 버튼이 나타납니다. 다른 탭을 보거나 다른 창으로 이동하거나 게임을 닫은 시간은 제외합니다. 재접속해도 이전에 쌓인 대기 시간부터 이어집니다.

선물상자를 클릭하면 현재 상황에 맞는 한 문장이 나옵니다. 플레이어 위치와 관계없이 **사진관 → 학교 → 놀이공원 → 놀이터 → 집** 순서로 아직 끝내지 않은 활동의 힌트를 고릅니다. 한 장소에 남은 힌트가 여러 개면 그 장소 힌트를 모두 준 뒤 다음 장소로 넘어갑니다. 필요한 아이템이 없는 활동은 해당 아이템을 구하는 활동으로 안내합니다. 사진·게시판·자리표·약도·낙서·비눗방울 등의 최초 확인은 진전이며, 같은 것을 다시 보거나 같은 시설을 다시 이용하는 것은 타이머를 초기화하지 않습니다. 힌트를 보는 것 자체도 진전으로 세지 않습니다.

진전 없이 **6분·9분**이 되면 🎁가 다시 나타나 힌트를 하나씩 더 받을 수 있습니다(최대 3개). 추가 힌트는 이번 대기 동안 아직 받지 않은 힌트 중 같은 순서로 다음 것입니다. 9분 이후에는 더 늘지 않으며, 새 진전이 생기면 다시 3분부터 시작합니다. 개수는 `data/hints.js`의 `maxHints`에서 바꿉니다. 이번 대기 동안 받은 힌트는 `gameState.hints.received`에 저장합니다.

별도의 힌트 기록 버튼은 없습니다. 힌트를 한 번이라도 받으면 🎁는 계속 남아 있습니다. 누르면 새 힌트가 있을 때는 위에 새 힌트를, 아래에 **이전에 본 힌트**를 모두 보여주고, 새 힌트가 없을 때는 이전에 본 힌트만 보여줍니다. 같은 힌트는 기록에 중복 추가하지 않습니다. 패널이 열려 있는 동안 이동과 배경 클릭은 차단하며 닫기 버튼으로 닫습니다. 다른 조사·인벤토리·업적 창을 닫은 뒤 사용할 수 있습니다.

집에 들어가기 전에는 집 힌트를 HNT-07 → HNT-13(집 외곽) 순서로 주고, 그다음 미끄럼틀 힌트(HNT-14)를 줍니다. HNT-14는 놀이터 힌트지만 이 경우만 장소 순서의 예외입니다.

- `data/hints.js`: 사용자가 제공한 표의 확정 문장 8개, 추가 임시 문장(TODO), 진전·단서 목록, 시간 설정.
- `hints.js`: 상황별 후보 선택, 실제 표시 시간 누적, 최초 진전 감지, 힌트 패널·기록.
- `gameState.hints`: `history`, `clues`, `lastProgressAt`(시각), `idleMs`(실제 표시 시간)를 자동 저장합니다.
- `node verify-hints.cjs`: 확정 문장 일치, 시간 경계, 탭·창 전환 제외, 중복 진전 방지, 기록·시간 복원, 1버전 변환, 상황 선택·입력 차단을 검사합니다.

디버그 모드와 일반 플레이 모두 새 진전 없이 **3분** 기다리면 왼쪽 선물상자가 나타납니다. 대기 시간은 `data/hints.js`의 `HINT_DATA.waitMs`와 `debugWaitMs`에서 바꿀 수 있습니다. 설정을 바꾼 뒤에는 게임을 새로고침하세요.

## 사진첩과 인벤토리 확인

1. 사진관에 들어가 왼쪽 아래 소파 앞 탁자 가까이로 이동합니다.
2. 탁자 위 보라색 **사진첩**을 클릭한 뒤, 열린 사진첩 안의 **사진을 클릭**해야 돌잔치 사진을 획득합니다. 획득 후에는 빈 자리가 남고, 다시 방문해도 중복 지급되지 않습니다.
3. `I`로 인벤토리를 열고 사진을 클릭하면 선택 강조와 확대창이 나타납니다. 앞면의 날짜는 `2003.09.01`입니다. 확대된 사진을 클릭할 때마다 앞면·뒷면이 바뀌며, 다시 열면 앞면부터 보입니다. 뒷면 도로선은 최종 이미지가 아닌 임시 그림입니다.
4. `I` 또는 **닫기** 버튼으로 닫습니다. 열린 동안 이동과 배경 클릭은 차단됩니다. 수량 제한과 버리기 기능은 없습니다.

입구 왼쪽 카운터의 **직원** 가까이에서 클릭하면 기획서의 확정 대사가 나옵니다. 직원과 대화하지 않아도 사진을 얻을 수 있습니다.

대사창·사진첩·확대창은 **닫기** 버튼으로 닫습니다. 열린 동안 이동·배경 클릭을 차단합니다. 확대창만 닫으면 인벤토리로 돌아오며, 확대 중 `I`를 누르면 인벤토리까지 닫힙니다. 아이템 선택은 유지됩니다.

업적 목록은 Tab으로 확인합니다. 아이템과 획득 상태는 자동 저장됩니다. 사진 획득 여부는 `gameState.photoCollected`에 기록하며 보유 목록·획득 기록과 함께 갱신합니다.

- `data/items.js`: ITM-01~ITM-10의 ID·이름·용도
- `data/objects.js`: 사진첩·직원·테이블의 위치와 크기, 조사 거리(`interactDistance`), 획득 아이템·확정 대사·안내 문구. 좌표는 실내 픽셀 기준입니다.
- `game-state.js`: 보유 아이템·선택 항목·획득 기록을 모은 `gameState`와 중복 획득 검사
- `inventory-list.js`: 나중에 교체할 수 있도록 분리한 목록 UI
- `inventory-ui.js`: 인벤토리 열기·닫기와 선택 처리
- `studio-ui.js`: 직원 대사창, 사진첩 획득, 사진 확대·앞뒤 전환
- `node verify-inventory.cjs`: 조사 거리, 중복 획득, 입력 차단, 선택 유지와 아이템 데이터를 검사합니다.

## 학교 실내

학교 실내는 문 닫힌 그림 `assets/school-doors-closed.png`와 문 열린 그림 `assets/school-doors-open.png`(각 887×1774, 위쪽 절반이 1층·아래쪽 절반이 2층)를 겹쳐 그립니다. 원본은 `에셋/`의 "학교 내부 문 닫힌 버전", "학교 내부 문 열린 버전"입니다. 두 그림은 문 부분만 달라서, 닫힌 그림을 깔고 열린 문 자리만 열린 그림에서 잘라 덮습니다. 그림 1픽셀은 1층에서 게임 속 3.5픽셀, 2층에서 4.5픽셀입니다(층마다 `scale`). 사용자 요청으로 1층만 작게 했고, 2층은 9반 책상 30개가 들어가도록 유지합니다. 그림을 불러오지 못하면 바닥과 문을 임시 색 블록으로 그립니다.

- **문 열기·닫기**: 열 수 있는 문 가까이에 가면 화면에 "E 키를 누르거나 문을 클릭해 열기"(열린 문은 "…닫기") 안내가 나옵니다. 문 열기 키를 바꾸면 바뀐 키 이름이, 키가 할당 없음이면 "문을 클릭해 열기"가 나옵니다. **E**를 누르거나 문을 클릭하면 열리고, 다시 누르면 닫힙니다. 닫힌 문은 지나갈 수 없습니다. 문 틈에 서 있으면 닫히지 않고 "문 앞에서 비켜 주세요."가 나옵니다. 멀리서 문을 클릭하면 "문 가까이에서 클릭해 주세요."만 나옵니다.
- 열린 문은 학교를 나가면 모두 닫힙니다. 층을 오가는 동안은 유지되며, 문 상태는 저장하지 않습니다. 문 틈에 선 채로 저장된 게임을 이어 하면 그 문만 열린 채로 시작합니다.
- E 키는 설정 화면의 **상호작용(문·건물 출입, 계단, 대화)**에서 바꿀 수 있습니다. 사진관의 사진작가와 학교 선생님에게도 E 키로 말을 걸 수 있고, 가까이 가면 안내 문구가 나옵니다(`data/objects.js`, `data/school.js`의 `keyHint`). 대화창은 E 키로 다시 닫을 수 있습니다. E 키 안내는 플레이어가 아니라 대상 바로 위에 나옵니다. NPC는 머리 위, 그 밖의 대상(게시판·문·계단·건물 입구·출구)은 대상 한가운데입니다. 건물 입구 위치는 `city-data.js`의 `hintOffset`으로 맞추며, 집 쪽문은 플레이어를 가리지 않도록 문 윗부분입니다(`game.js`의 `currentKeyHint`, `KEY_HINT_BOX`). 반 배치 게시판도 E 키로 열고 닫을 수 있습니다. 이전에 저장한 키 설정에는 이 항목이 없으므로, 기존 키는 그대로 두고 이 항목만 기본값(E)으로 채웁니다. E를 이미 다른 기능에 쓰고 있었다면 할당 없음이 됩니다.
- 정문은 사용자 결정으로 항상 열린 그림(유리문 없음)을 씁니다. 현관 안쪽 끝의 **나가기**를 클릭하면 밖으로 나갑니다.
- **1층**: 정문으로 들어오면 로비입니다. 위쪽 왼쪽이 **교무실**, 오른쪽이 **보건실**, 가운데가 **2층 계단**입니다. 로비 왼쪽 게시판이 **반 배치 게시판**이고, 그 오른쪽 아래에 선생님이 있습니다.
- **2층**: 가운데 복도를 중심으로 위쪽 줄에 1~4반(가운데 계단), 아래쪽 줄에 5~9반이 있습니다. 9반은 오른쪽 아래 교실입니다.

## 놀이공원 확인

놀이공원은 도시 그림 오른쪽 아래의 분홍 광장(대표점 `(1243, 562)`)이며 실내 전환이 없습니다. 아래쪽 큰길의 아치 정문이나 위쪽 큰길의 분홍 길로 들어갑니다(위쪽 길은 사용자 결정으로 기획서의 진입로 한 곳과 다릅니다). 다른 가장자리는 보이지 않는 울타리로 막았습니다. 광장 안 양쪽 화단은 지나갈 수 없습니다.

1. 정문 바로 안쪽 **매표소**에 가까이 가서 매표소 위 노란 **머리띠**를 클릭합니다. ITM-04가 한 번만 들어갑니다.
2. 중앙 **회전목마**에는 말 5개와 마차 3개가 정지 상태로 원형 배치되어 있습니다. 사용자 결정(2026-11-08)으로 회전목마 그림에 맞춰 가림 없이 모든 탈것이 보입니다. 기획서(말 6·마차 3, 일부 탈것이 가려짐)와 다릅니다.
3. 오른쪽 위 외곽 **기념품 판매대** 가까이에서 클릭하면 잠금장치 화면이 열립니다. 말과 마차의 개수를 입력하고 **확인**을 누릅니다. 오답이면 확인 버튼 아래에 빨간 안내(`PARK_DATA.text.wrong`)가 나오고 입력 상태는 유지됩니다. 정답이면 초록 안내(`PARK_DATA.text.correct`)가 나옵니다. 사용자 결정으로 기획서 AMP-04의 '오답 안내 없음'과 다릅니다.
4. 말 `5`, 마차 `3`이 정답입니다. 관찰 여부·아이템 보유에 관계없이 정답을 입력할 수 있습니다. 해결하면 `gameState.carouselSolved`가 `true`가 되고 판매대 옆 거치대에 풍선이 표시됩니다.
5. **닫기** 버튼으로 화면을 닫습니다. 잠금창이 열린 동안 이동과 배경 클릭을 막습니다. 다시 방문해도 해결 상태가 유지됩니다.
6. 거치대 가까이에서 **풍선 자체를 클릭**하면 풍선(ITM-05)을 얻고 놀이터 메모가 열립니다. 메모의 **닫기** 버튼을 누르면 메모(ITM-06)가 인벤토리에 들어갑니다. 반복 클릭하거나 다시 닫아도 중복 지급되지 않습니다.
7. 인벤토리에서 메모를 선택하면 약도를 다시 볼 수 있습니다. 그네는 왼쪽 위, 미끄럼틀은 오른쪽 위, 시소는 오른쪽, 출입구는 왼쪽 아래입니다. 방향 표식이나 회전 기능은 없습니다. 닫기 버튼은 인벤토리로 돌아가고 `I`는 인벤토리까지 닫습니다.

## 놀이터와 비눗방울 장난감

놀이터는 도시 그림 왼쪽의 모래 놀이터(대표점 `(365, 598)`)입니다. 아래쪽 벽돌 기둥 사이 출입구 한 곳으로 들어가며 맵 전환은 없습니다. 그네는 북서쪽, 시소는 동쪽, 미끄럼틀은 북동쪽입니다. 서쪽 외곽의 큰 나무는 도시 랜드마크 `L04`입니다. 놀이터 약도를 보지 않아도 입장·이용할 수 있습니다.

1. 그네 가까이에서 클릭하면 2초간 움직이며 `gameState.swingUsed`가 기록됩니다.
2. 시소도 가까이서 클릭하면 움직이며 `gameState.seesawUsed`가 기록됩니다. 재클릭하면 다시 움직이고, 연출 중에도 걸어 다닐 수 있습니다.
3. 둘을 모두 이용하면 놀이터 안에 큰 선물상자가 나타납니다. 이용 순서는 상관없습니다.
4. 상자를 가까이서 클릭하면 비눗방울 장난감(ITM-07)을 한 번만 얻고 상자는 사라집니다.
5. `I`로 인벤토리를 열어 장난감을 선택하고 닫습니다. 게임의 빈 바닥을 클릭하거나 마우스 왼쪽 버튼을 누른 채 드래그하면 플레이어 주변에 비눗방울이 생깁니다. 실내에서도 사용 가능하며 장난감은 소모되지 않습니다.

비눗방울 속 곰은 **갈색 털·둥근 귀·파란 리본**을 가진 임시 그림입니다. 약 3초간 떠오르다 사라집니다. 드래그 생성 간격과 최대 표시 개수를 제한해 오래 사용해도 계속 쌓이지 않게 했습니다. 문·시설·조사 물체 클릭은 기존 기능을 우선합니다. 인벤토리나 조사창이 열려 있으면 생성되지 않습니다.

미끄럼틀 몸체를 가까이에서 클릭하면 약 2초간 임시 인물이 내려오는 탑승 연출을 보여주고 `gameState.slideUsed`를 기록합니다. 다시 클릭하면 연출만 반복합니다. 실제 플레이어 위치는 바뀌지 않습니다.

상단 출발 구멍 위에 **조심히 타세요!** 표지가 있으며, 그 오른쪽 낙서를 가까이서 클릭하면 확대창이 열립니다. 왼쪽 그림은 놀이터에서 본 집의 방향을, 오른쪽 그림은 잠긴 정문과 오른쪽 담장의 나무 쪽문으로 이어지는 좁은 골목을 암시합니다. 화살표 방향은 지도 데이터에서 계산하므로 새 지도에서는 북동쪽을 가리킵니다. `slide.js`의 임시 그림에는 `TODO`가 있으며 실제 `R16` 도로·집 건물·쪽문 접근 좌표를 참조합니다. 낙서창은 **닫기** 버튼으로 닫습니다. 낙서를 읽지 않아도 탑승하거나 집 쪽문으로 들어갈 수 있습니다.

그네·시소·미끄럼틀을 모두 한 번 이상 이용하면 `gameState.achievementConditions["ACH-04"]`를 기록합니다. 이용 순서는 상관없고, 선물상자 등장·장난감 획득·낙서 확인은 업적 조건에 포함하지 않습니다. 선물상자는 기존처럼 그네·시소만 이용해도 나타납니다.

- `data/playground.js`: 임시 시설 위치·크기, 울타리와 출입구, 조사 거리, 연출 시간, 장난감 ID·문구.
- 시설 그림: 그네·시소·미끄럼틀·선물상자는 `assets/playground-swing.png`, `playground-seesaw.png`, `playground-slide.png`, `playground-gift.png`를 사용합니다(`에셋/`의 원본을 영문 이름으로 복사). 그네·시소 그림은 2줄×5칸 10장면이며, 클릭하면 장면을 차례로 재생하고 멈추면 `restFrame` 장면을 보여줍니다. 그림 경로·칸 수·자를 범위(`crop`)·장면 속도(`frameMs`)는 `PLAYGROUND_DATA.sprites`에서 바꿉니다. 그림을 불러오지 못하면 임시 도형으로 그립니다. `BUBBLE_DATA`는 비눗방울 크기·수명·생성 간격과 곰의 외형 설정입니다.
- `playground.js`: 시설 그리기·충돌·이용 기록·선물상자 처리.
- `bubbles.js`: 배경 클릭·드래그와 비눗방울 연출. 맵이 바뀌면 이전 연출은 지웁니다.
- `slide.js`: 미끄럼틀 표지·출발 구멍·탑승 연출과 낙서 확대. 낙서 크기·위치·연출 시간은 `data/playground.js`의 `slideDetail`에서 조절합니다.
- `node verify-slide.cjs`: 클릭 영역 분리, 6가지 시설 이용 순서, 선물과 업적 독립, 실제 골목 좌표, 낙서 전후 집 쪽문 출입을 검사합니다.
- `node verify-playground.cjs`: 약도 없이 접근, 시설 배치·이용 순서·재이용, 상자 중복 방지, 실내외 사용·조사 우선·비소모·수명 검사를 실행합니다.

새 파일을 제공하려면 실행 중인 서버를 `Ctrl+C`로 종료한 뒤 `node server.cjs`로 다시 시작하고 새로고침하세요. 시설별 이용·획득 기록은 자동 저장됩니다.

## 집 실내와 인형

집은 오른쪽 담장의 나무 쪽문을 클릭해 들어갑니다. 아이템이나 단서 확인은 필요하지 않고, 남쪽 정문은 계속 잠겨 있습니다. 실내는 `assets/house-interior.png` 그림(그림 1픽셀 = 게임 1픽셀)을 그대로 씁니다. 아래쪽 현관에서 들어와 마루로 이어지고, 마루 위쪽 왼쪽 문이 **아이 방**(별 이불 침대), 오른쪽 문이 **안방**(분홍 침대)입니다. 사용자 결정으로 **부엌은 벽으로 막혀 들어갈 수 없습니다**(기획서와 다름). 안방 문은 항상 열려 있어 문 그림 대신 바닥 그림으로 덮어 그립니다.

인형은 안방 침대 위에 있고, 침대 옆 바닥에서 클릭하면 각각 한 번만 획득합니다. 곰 인형은 `ITM-08`입니다. 사용자 결정으로 고양이 인형 대신 돼지 인형을 씁니다(그림이 돼지뿐이라 기획서와 다름). 곰 인형 그림의 리본은 빨강이고, 기획서의 파란 리본과 다릅니다. 다른 인형도 인벤토리에 남지만 `cabinetUsable: false`로 장식장 사용 불가를 명시했습니다.

| 인형 | 물체 ID | 아이템 ID | 장식장 사용 |
| --- | --- | --- | --- |
| 곰 | DOLL-01 | ITM-08 | 가능 |
| 토끼 | DOLL-02 | DOLL-ITEM-02 | 불가 |
| 강아지 | DOLL-03 | DOLL-ITEM-03 | 불가 |
| 돼지 | DOLL-04 | DOLL-ITEM-04 | 불가 |
| 돌고래 | DOLL-05 | DOLL-ITEM-05 | 불가 |

아이 방 문은 `ITM-09` 열쇠를 보유한 상태로 가까이에서 클릭해야 열립니다. 열쇠 없이 걸어 들어가거나 문을 눌러도 들어갈 수 없습니다. 열린 상태는 `gameState.childRoomUnlocked`로 관리합니다. 열쇠는 마루 장식장을 완성하면 자동 지급됩니다.

- `city-data.js`의 `interiors`: 집 그림 경로, 걸을 수 있는 바닥(`walkable`), 가구 장애물(`obstacles`). 좌표는 그림 픽셀입니다.
- 장식장은 마루에 닫힌 그림(`assets/cabinet-closed.png`, 원본 `에셋/닫힌 장식 진열장.png`)으로 놓이고, 클릭하면 배치 화면에 열린 그림(`assets/cabinet-open.png`, 원본 `에셋/열린 장식 진열장.png`)이 나옵니다. 그림의 칸은 6개이고 퍼즐은 5칸이라 왼쪽→오른쪽·위→아래로 1~5번을 놓고 오른쪽 아래 칸은 비워 둡니다. 칸 위치는 `data/cabinet.js`의 `slotRects`에서 바꿉니다.
- `data/house.js`: 방·문·장식장·인형 위치와 크기, 인형 그림(`sprite`), 인형 ID와 장식장 사용 속성.
- `house.js`: 잠긴 문·인형 충돌, 열린 문·인형 그리기와 획득, 아이 방 열쇠 검사.
- `bubbles.js`의 `drawBearDoll`: 그림을 불러오지 못했을 때 쓰는 임시 곰 인형.
- `node verify-house.cjs`: 방·인형 접근, 부엌 차단, 고유 ID·중복 방지, 아이 방 잠금·열쇠 개방, 정문·쪽문 출입을 검사합니다.

서버를 재시작하고 새로고침한 뒤 **쪽문 입장 → 오른쪽 위 안방 침대의 인형 클릭 → I로 인벤토리 확인**으로 확인하세요. 아이 방 잠금 해제도 자동 저장됩니다.

### 업적 목록과 알림

게임 화면에서 **Tab**으로 업적 목록을 열고, **Tab 또는 닫기 버튼**으로 닫습니다. 열려 있는 동안 이동과 배경 클릭은 막힙니다. 인벤토리·일기장 등 다른 창에서는 해당 창을 닫은 뒤 업적을 열 수 있습니다.

처음에는 ACH-01만 `active`(진행 중)이고 나머지는 `hidden`(숨김)입니다. 조건을 만족하면 방문 순서와 상관없이 해당 업적만 `completed`(달성 완료)가 됩니다. 안내는 가장 앞선 미완료 업적을 가리키며, 이미 완료한 업적은 건너뜁니다. 숨긴 업적은 목록에 표시하지 않습니다.

달성 시 오른쪽 위에 3초 알림이 나타납니다. 동시에 여러 개를 달성하면 하나씩 알리며, 같은 업적은 반복 알리지 않습니다. `gameState.achievements`는 자동 저장되며 복원 시 달성 알림을 반복하지 않습니다. 업적 6개 완료는 엔딩 조건이 아니며, 일기장 3페이지에서 닫으면 `endingReached`를 기록합니다.

- `data/achievement-conditions.js`: 기획서 6.3의 업적 이름·조건, 순서, 알림 시간(TODO).
- `achievements.js`: 목록, Tab 입력, 순차 알림.
- `node verify-achievements.cjs`: 720가지 달성 순서, 안내 전환, 독립 조건, 입력 차단, 알림 시간·중복 방지, 엔딩 독립성을 검사합니다.

서버를 재시작(`node server.cjs`)하고 새로고침한 뒤 **Tab → 첫 업적 확인 → 닫기 → 사진 획득 → 알림과 Tab 목록 확인**으로 확인하세요. 학교 조건을 먼저 채우면 ACH-02만 완료되고 ACH-01 안내가 유지됩니다.

### 아이 방과 일기장

장식장에서 얻은 열쇠(ITM-09)를 보유하고 아이 방 문을 가까이에서 클릭하면 열립니다. 아이 방 오른쪽 침대 위 일기장을 가까이에서 클릭하면 확대 화면이 열리고, 일기장(ITM-10)이 인벤토리에 한 번만 들어갑니다. 최초 발견은 `diaryDiscovered`와 ACH-06 조건으로 기록합니다.

일기장은 `eh_Childhood.pdf` PART 5.1의 제목과 줄바꿈을 반영한 3페이지입니다. `다음 페이지`로 넘긴 뒤 **3페이지에서 공책 본문 또는 닫기 버튼을 한 번 더 클릭하면** `endingReached`를 기록하고 엔딩을 시작합니다. 3페이지로 넘기는 클릭은 확인으로 세지 않습니다. 1~2페이지의 닫기와 인벤토리 키로 닫기는 완료되지 않습니다. 다시 열 때는 항상 1페이지부터 시작합니다.

실행 중인 서버를 `Ctrl+C`로 종료하고 `node server.cjs`로 다시 실행한 뒤 브라우저를 새로고침하세요. **열쇠 획득 → 아이 방 문 클릭 → 침대의 일기장 클릭 → 다음 페이지 두 번 → 공책 본문 또는 닫기 클릭** 순서로 확인합니다. 발견·읽기 완료는 자동 저장됩니다.

일기장은 로컬 `assets/Gaegu-Regular.ttf`를 사용합니다. **Gaegu Regular (JIKJI SOFT), SIL Open Font License 1.1**이며 공식 라이선스는 `assets/Gaegu-OFL.txt`에 있습니다. 인터넷 없이 표시되며, 원본 폰트를 변경하지 않고 글자별 크기·기울기·기준선을 조금씩 바꿉니다. 공책 줄과 종이 질감은 임시 CSS 그림입니다.

엔딩은 사진 → 책상·크레파스 → 회전목마 → 곰 비눗방울 → 집 → 어린 주인공과 현재 주인공 순서로 각각 1.5초, 총 9초 동안 부드럽게 나타났다가 사라집니다. 회상 중에는 이동·메뉴·개발용 초기화 등 다른 조작을 막으며 건너뛰기는 없습니다. 회상 그림은 TODO 임시 그림입니다.

회상 **시작 시** `endingReached`와 `endingCompleted`를 모두 기록하고 저장합니다. 중간에 새로고침해도 자동 재생하지 않고 마지막 위치에서 맵 전체를 자유롭게 탐색합니다. 아이템·퍼즐·업적은 유지됩니다. 일기장을 다시 읽고 마지막 페이지를 확인하면 회상을 다시 볼 수 있습니다. 이전 저장의 `endingReached`도 새 완료 값으로 변환합니다.

암전 후 화면 가운데에 **다시 시작 / 게임 종료**가 나타납니다. 다시 시작은 기존 확인창을 거쳐 진행만 초기화하고 키·소리 설정은 유지합니다. 게임 종료는 저장한 뒤 **게임이 종료되었습니다. 탭을 닫아주세요.** 안내만 표시합니다. 같은 주소에 재접속하거나 새로고침하면 자유탐색으로 이어집니다.

`data/ending.js`의 `scenes`에서 장면별 `title`, `durationMs`, `background`, `image`를 관리합니다. 최종 그림을 `assets/`에 넣고 `image: "assets/파일명.png"`처럼 지정하면 임시 그림 대신 표시합니다. 파일명은 영문·숫자·하이픈·밑줄을 사용하고 PNG/JPG/WebP/SVG를 지원합니다. 이미지 로딩에 실패하면 임시 그림을 유지합니다.

- `data/diary.js`: 기획서 문장, 화면 문구, 임시 침대·일기장 위치와 크기, 조사 거리.
- `diary.js`: 발견·획득, 페이지 표시, 읽기 완료와 엔딩 연결 지점.
- `style.css`: 로컬 손글씨 폰트, 글자별 변화, 임시 공책 배경.
- `data/ending.js`, `ending.js`: 장면별 시간·문구·이미지 교체 경로, 임시 그림·종료 메뉴·종료 안내.
- `node verify-ending.cjs`: 추가 클릭 판정, 페이지 넘김과 구분, 9초 회상, 반복 방지, 저장, 종료 메뉴를 검사합니다.
- `node verify-diary.cjs`: 잠금·조사 거리·중복 획득·페이지 초기화·닫기 시 완료·인벤토리 재열기·문장 일치를 검사합니다.

### 마루 장식장

장식장 가까이에서 클릭하면 위에서부터 1~5번 칸과 보유 아이템 목록이 열립니다. 목록에서 아이템을 선택하고 칸을 클릭해 배치합니다. 배치한 아이템을 클릭한 뒤 다른 칸을 클릭하면 이동하며, 이미 차 있는 칸이면 서로 바뀝니다. 목록에서 가져온 아이템으로 차 있는 칸을 교체하면 기존 아이템은 인벤토리로 돌아갑니다.

정답은 위에서부터 **돌잔치 사진 → 크레파스 → 머리띠 → 비눗방울 장난감 → 곰 인형**입니다. 이 다섯 종류만 배치할 수 있고, 틀린 칸에 놓는 것은 가능합니다. 미완료 상태에서 닫거나 장소를 떠나면 배치를 초기화하고 모두 인벤토리로 돌려놓습니다.

완성하면 다섯 아이템은 장식장에 고정되고 열쇠가 한 번만 지급됩니다. `cabinetSolved`, `cabinetKeyGranted`, `achievementConditions["ACH-05"]`에 결과를 자동 저장합니다. 열쇠를 얻은 뒤 아이 방 문을 가까이에서 클릭하면 열립니다.

- `data/cabinet.js`: 정답 순서·허용 아이템·배치 규칙·화면 문구.
- `cabinet.js`: 배치 화면·교환·반환·정답 처리. 창을 닫을 때 `restoreUnsolvedCabinet()`으로 반환하며, 저장 사본과 불러오기에서는 `save.js`가 동일한 반환 규칙을 적용합니다.
- `node verify-cabinet.cjs`: 자유 배치, 교환, 닫기/퇴장 시 반환, 중복 방지, 열쇠 지급 및 아이 방 개방을 검사합니다.

## 기본 파일 목록

- `index.html`: 게임 화면과 스크립트 로딩
- `style.css`: 화면 스타일
- `city-data.js`: 도시 그림 경로, 보행 도로 좌표·폭, 장소·장애물·랜드마크, 출입문·접근 지점, 임시 실내와 출입 설정
- `assets/city-map.png`: 도시 그림. `에셋/햇살 가득한 맵.png`를 영문 이름으로 복사한 파일입니다.
- `game.js`: 그리기, 입력, 이동 가능 영역, 충돌, 카메라, 문 클릭과 맵 전환
- `server.cjs`: 로컬 실행 서버
- `verify-city.cjs`: 실제 이동 판정으로 길 연결을 검사하는 스크립트
- `verify-interiors.cjs`: 문 클릭·잠금·실내 이동·퇴장 위치·카메라를 검사하는 스크립트

현재 위치는 자동 저장되며 새로고침하면 마지막 저장 위치에서 이어집니다. 저장이 없는 새 게임은 도시 중앙에서 시작합니다.

## 도시 그림과 보행 구역

길이 다른 길과 만나는 끝은 둥글게 처리됩니다. 끝점을 큰길 안쪽에 두어야 합니다. 끝이 큰길 반대쪽으로 튀어나오면 플레이어가 그 안에 들어갔을 때 좌우로 움직일 수 없습니다. `verify-city.cjs`가 주요 길 끝에서 좌우 이동을 검사합니다.

도시는 `assets/city-map.png`(1672×941) 그림을 그대로 깔고 그립니다. 그림의 픽셀 위치가 곧 논리 좌표입니다. 예를 들어 그림에서 가로 748, 세로 612에 있는 별은 논리 좌표 `(748, 612)`입니다. 기획서 PART 2의 좌표 대신 그림 배치를 따르기로 사용자가 결정했습니다(2026-11-07).

그림은 보기만 하는 배경입니다. 실제로 걸을 수 있는 곳은 `city-data.js`의 데이터로 따로 정합니다. 그림을 바꾸거나 길을 고치면 이 데이터도 함께 맞춰야 합니다.

| 장소 | 대표점(논리 좌표) | 들어가는 곳 |
| --- | --- | --- |
| 사진관 | (1230, 121) | 오른쪽 위. 위쪽 큰길에서 앞마당을 지나 정문 |
| 학교 | (442, 125) | 왼쪽 위. 위쪽 큰길에서 앞마당을 지나 정문 |
| 놀이공원 | (1243, 562) | 오른쪽 아래. 아래쪽 큰길의 아치 정문 |
| 놀이터 | (365, 598) | 왼쪽. 아래쪽 큰길의 벽돌 기둥 사이 출입구 |
| 집 | (846, 100) | 위쪽 가운데. 정문은 잠김. 오른쪽 세로 길에서 골목 `R16`을 지나 나무 쪽문 |

- `roads`: 걸을 수 있는 길. `points`는 길 가운데 선, `width`는 길 폭(그림 픽셀)입니다. 점이 두 개 같으면 원형 광장이 됩니다(`R04`).
- `locations`: 장소 건물·야외 구역. 건물(`solid: true`)은 지나갈 수 없습니다. 놀이공원은 `walkArea` 다각형 안, 놀이터는 사각형 안을 걸을 수 있습니다.
- `doors`: 문 위치와 크기(`width`, `height`). 집 쪽문처럼 건물 밖 담장에 있는 문은 `x`, `y`를 직접 적습니다. `side`는 플레이어가 서는 쪽(`north`·`south`·`east`·`west`)입니다.
- `obstacles`: 그림 속 화단처럼 지나갈 수 없는 사각형입니다.
- `landmarks`: 시계탑(학교 시계) `(441, 85)`, 연못 `(1505, 115)`, 큰 나무 `(30, 590)`. 그림에 분수대가 없어 `L01`은 뺐습니다.
- `accessPoints`: 각 문 앞 발밑 위치. `node verify-city.cjs`가 시작점에서 이곳까지 걸어갈 수 있는지 검사합니다.
- 그림을 불러오지 못하면 같은 데이터로 회색 길과 사각형 건물을 그립니다.

`city-data.js`에서 `debug: true`로 바꾸면 장소 ID·좌표와 문 앞 위치(빨간 점)가 그림 위에 표시됩니다.

## 월드 크기와 이동 속도 조절

`game.js` 상단의 `settings` 값을 수정하고 저장한 뒤 브라우저를 새로고침합니다.

```js
const settings = {
  worldScale: 3,
  locationScale: 3,
  cameraZoom: 0.75,
  playerSpeed: 630,
  mapSmoothing: false,
};
```

- `worldScale`: 그림 1픽셀을 화면 몇 픽셀로 키울지 정합니다. 기본값 `3`은 5016×2823픽셀 월드입니다.
- `locationScale`: `worldScale`과 같게 둡니다. 장소 크기를 그림 픽셀 그대로 쓰기 위해서입니다.
- `cameraZoom`: 화면 확대 배율입니다. 1보다 작을수록 멀리서 넓게 보입니다(현재 0.75). 캐릭터의 실제 크기와 충돌 범위는 그대로입니다.
- `playerSpeed`: 초당 월드 이동 픽셀 수입니다.
- `mapSmoothing`: `false`는 확대한 그림의 픽셀이 또렷하게, `true`는 부드럽게 보입니다.

## 확인 방법

- 방향키로 이동하면 화면이 플레이어를 따라 움직이고, 그림 끝에서는 멈춥니다.
- 포장된 길·광장·놀이터·놀이공원 바닥만 걸을 수 있습니다. 잔디·나무·건물·연못·화단으로는 들어가지 못합니다.
- 놀이공원·놀이터는 들어가도 야외 맵을 유지합니다.
- 집 정문은 가까이에서 눌러도 잠금 안내만 나옵니다. 오른쪽 세로 길에서 나무 쪽문으로 들어가고, 나올 때도 쪽문 앞으로 나옵니다.
- 실내에서는 문을 클릭해야 나갑니다. 먼 곳에서 문을 클릭하면 가까이 이동하라는 안내가 나옵니다.
- `node verify-city.cjs`: 그림 기준 좌표, 잔디·숲·연못·화단 충돌, 쪽문 골목, 큰길, 시작점에서 6개 문 앞까지의 경로를 검사합니다.
- `node verify-interiors.cjs`: 세 장소 왕복 출입, 집 정문 잠금, 퇴장 위치, 창 크기 변화에 따른 클릭 좌표를 검사합니다.

## 실내 설정

`city-data.js`의 `interiors`에서 출구·시작 위치와 그림(`picture`)을 수정할 수 있습니다. 실내는 픽셀 단위이며 도시 배율을 적용하지 않습니다. 사진관은 `assets/studio-interior.png`를 0.8배(`scale`)로, 집은 `assets/house-interior.png`를 1배로 그립니다. `walkable`은 걸을 수 있는 바닥, `obstacles`는 가구이며 둘 다 그림 픽셀 좌표입니다. 그림을 불러오지 못하면 임시 색 블록으로 그립니다.

그 밖의 그림: 플레이어는 `assets/player-walk.png`(4칸×4줄, 줄 순서 아래·위·왼쪽·오른쪽)와 아래를 보고 서 있을 때의 `assets/player-front.png`를 씁니다. 크기와 걸음 속도는 `game.js`의 `PLAYER_SPRITE`에 있습니다. 학교에서만 플레이어를 1.5배로 그립니다(`placeScale`). 부딪히는 범위는 그대로입니다. 선생님 그림은 `data/school.js`에서 2.5배로 키웠습니다. 사진작가·선생님은 `assets/npc-*.png`, 아이템 아이콘은 `assets/item-*.png`(`data/items.js`의 `icon`), 비눗방울은 `assets/bear-bubble.png`, 풍선 거치대는 `assets/park-stand.png`입니다. 모두 `에셋/` 원본에서 배경을 지우고 잘라 낸 사본입니다.

`entrances.interactDistance`는 출입 가능한 거리(기본 100픽셀), `clickPadding`은 문 클릭의 여유 범위(12픽셀), `cooldownMs`는 연속 클릭으로 즉시 재전환되는 것을 막는 시간(250밀리초)입니다.
